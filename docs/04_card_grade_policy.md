# 1. 목적

- 게임 내 카드의 희소성, 성능(OVR/성장 한계), 샐러리 비용을 통제하여 덱 구성의 전략성을 부여한다.
- 등급이 나중에 추가되더라도 기존 세이브 파일이 깨지지 않도록 Enum 및 테이블 구조를 사전 정의한다.

# 2. 전체 카드 등급 체계 (Enum: Grade)

_※ v0.1에서는 ID 1, 2(LIVE_NORMAL/LIVE_EPIC)만 활성화하며, 3 이상은 코드(Enum)와 DB 스키마에만 존재함._

**[v0.2 갱신, TASK-KBO-155 - 사용자 직접 지시]** 기존 `SEASON`(ID 0) 등급을 전면 삭제했다 - "무/소과금 기본 베이스"라는 역할은 이제 `LIVE_NORMAL`이 단독으로 맡는다(0번 값은 재사용하지 않고 영구 결번 처리한다). 신규 등급 `RETIRED_NUMBER`(영구결번)를 추가했다 - 표의 나열 순서상으로는 `DYNASTY` 다음에 적었지만, **실제 게임 내 성능/랭크는 `TITLE_HOLDER`와 `SIGNATURE` 사이**다(코드의 `Grade` enum 정수값도 이 성능 위치에 맞춰 `TITLE_HOLDER`와 `SIGNATURE` 사이에 배정했다 - `DYNASTY`보다 나열 순서가 뒤라고 해서 `DYNASTY`보다 강하다는 뜻이 아니다).

# 3. 등급 인플레이션 방지 및 가치 보존 원칙

1. **샐러리캡 절대 복종:** 상위 등급 카드가 무조건 이기는 구조를 막기 위해, 아무리 좋은 카드라도 샐러리 비용 공식 `기본 코스트 + (최종 OVR-60) + (각성*1.5)`에 종속된다. 왕조 카드로 도배하면 구단 예산 파산 또는 리그 등록이 불가능하다.
2. **미구현 데이터 처리 (Forward Compatibility):** v0.1 빌드에서 가챠 로직은 무조건 `LIVE_NORMAL`/`LIVE_EPIC` 2개 Enum만 반환하도록 하드코딩한다(TASK-KBO-155부터 `SEASON` 삭제로 활성 등급이 3개에서 2개로 줄었다). `SaveManager`는 Grade 자체를 JSON에 저장하지 않으므로(`Player.Template.TemplateId`로 원본을 다시 찾는 구조, `Types.cs` 클래스 요약 참고) 이 등급 체계 개편은 기존 JSON 세이브 파일을 깨뜨리지 않는다.
3. **왕조(DYNASTY) 세트덱 보너스 [TASK-KBO-166 구현 완료]:** 왕조 카드는 발급된 시즌 연도(예: 삼성 왕조는 2011~2014년 각각 별도 카드)와 무관하게, 같은 왕조 로스터에 속한 카드를 5명 이상 보유하면 그 왕조 기간 전체를 아우르는 세트덱 점수(팀 케미) `+15`를 받는다(일반 세트덱 `+12`와 별개로 가산 - 총 `+27`까지 가능). 자세한 판정 기준은 `docs/15_team_power_policy.md` 3절, 구현은 `GameManager.CalculateSynergy()`/`CalculateDynastySynergy()` 참고.
