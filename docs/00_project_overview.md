# 0. 게임명

- 게임명 : "스토브리그: 단장의 계절"

# 1. 게임 정체성 (Identity)

- **한 줄 피치:** 팬심과 예산을 쥐고 흔드는 단장이 되어, 스토브리그의 치열한 영입전과 치어리더 마케팅으로 나만의 왕조를 재건하는 KBO 프런트 시뮬레이션.
- **플레이어 역할:** 현장 개입(인게임 조작)을 최소화하고, 스쿼드 빌딩과 구단 살림(재정/팬심)을 책임지는 단장(GM).
- **핵심 판타지:** 한정된 예산 안에서 흙속의 진주를 발굴하고, 최고의 응원단으로 홈구장을 매진시키며 데이터 기반으로 스토브리그 성과를 증명하는 쾌감.
- 타겟 플레이어
  - 주 타겟 : 야구 팬 + 수집 육성 선호 유저. 게임에 돈을 지불할 의향이 있는 유저.
  - 서브 타겟 : 스포츠 매니저류 게임 유저, 야구팬 유저. 게임에 돈은 많이 쓰진 않지만 팬심으로 응원하는 구단으로 플레이하길 원하는 유저.
- **타깃 경험:** 엑셀과 통계를 다루며 나만의 로스터를 맞추고, 자동 시뮬레이션 결과를 보며 희열을 느끼는 매니지먼트 감성.

# 2. 성공 기준 (Success Criteria)

- **v0.1 (개인용):** 내가 직접 삼성 라이온즈 덱을 짜서 10시즌 연속 크래시 없이 돌리고, "싸게 데려온 FA가 성적을 내는 뽕맛"을 느낄 수 있는가.

## 4.1 게임의 방향성 (High Concept)

✅ **[구현 확정]** 한 줄 요약/플레이어 역할/핵심 판타지/타깃 경험/타겟 플레이어/성공 기준은 위 1~2절과 동일한
내용이며, 방향성이 그대로 유지되고 있습니다.

### 세션 길이

- 1회 플레이
  - 풀 플레이 : 지연 없이 플레이 하면 15~20분.
  - 하이라이트 : 시뮬레이션 + 중요한 순간 직접 플레이, 3~5분.
  - 빠른 진행 : 30초~1분.

> 🔁 **[변경됨, DCL-001/DCL-004]** "풀 플레이"(사용자가 직접 투구/타격 조작)와 "하이라이트 개입"은 폐기되었다.
> 현재는 유저 개입 없이 끝까지 자동으로 진행되는 단일 논스톱 관전 방식 1종만 존재한다(`PlayBallController`).
> 세션 길이 수치 자체는 참고용으로 보존하되, "직접 플레이"를 전제로 한 시간 구간은 더 이상 유효하지 않다.

### 플레이 보상

- 출석 보상은 성장 재료로 한다.
- 일간 플레이 보상은 성장 재료 + (일반)선수 영입을 위한 재화로 한다.
  - 출석체크: 매일 출석에 대한 적정 보상. 출석의 기준을 7일 혹은 매월(말일에 맞게)로 하여 보상. 7일로 할 경우, 7일 째 큰 보상. 매월 말일(28, 30, 31일 중)로 할 경우, 주 시작은 일요일, 매주 토요일 큰 보상. 놓친 보상은 소액 현질, 포인트로 구매할 수 있도록 함.
  - 일일 미션 강도
    - 리그 플레이타입 무관 1회 / 5회 / 30회 플레이
    - 랭킹 챌린지 1회 플레이
    - 강화 시도 1회, 훈련 시도 1회
    - 홈런 레이스 혹은 타점 배틀 1회
    - 일일 접속하기, 선수 스카우트 1회
    - 일일 미션 모두 완료
    - 일일 보상 : 완료 2개(선수 성장 재화 50,000P), 4개(2~4성)
  - 주간 보상 : 일일 미션 70회 누적

🕳️ **[TBD: 기획 확정 필요]** 출석/일일·주간 미션 시스템은 현재 코드베이스에 구현되어 있지 않다.

## 4.2 디자인 필러 (Design Pillars)

게임이 반드시 지켜야 할 5가지 원칙:

- **ELO** : 과금과 노력으로 얻은 강함은 확실히 보장하여 인정하되, 덱 편성의 지략으로 승부하게 만든다.
- **필러1** : 유저가 키운 선수, 치어리더, 구단이 성장하는 보상이 명확해야 한다.
- **필러2** : 실제 야구의 전술·상성이 승패에 영향을 줘야 한다.
- **필러3** : 무소과금도 핵심 콘텐츠는 즐길 수 있어야 한다.
- **필러4** : 과금 유저의 경우, 무소과금 유저의 비해 확실한 보상과 차이가 있어야 한다.
- **필러5** : KBO 비시즌 구간에 야구팬들에게 이어지는 야구 재미를 보장해야 한다.

**Non-Goals (명시적으로 하지 않을 것):**

- 오토 플레이 전량, PvP 강제 랭킹전, 확률 강화 실패·파괴
- 구단 세트덱 중심 플레이 방지 — 구단과 상관없이 성능이 좋은 선수들로만 구성하는 것을 방지. 같은 구단 소속 선수들을 모아 구성하면 팀 능력치와 OVR을 크게 올리는 핵심 시스템(세트덱 보너스).

✅ **[구현 확정]** 세트덱(구단 통일) 보너스 개념은 `Player.CalculateOVR(isSetDeckBonusActive, setDeckBonusMultiplier)`로 실제 구현되어 있다.

## 4.4 핵심 게임플레이

### 코어 루프 (Core Loop)

- 루프1 : 경기 → 결과/보상 → 카드 성장 → 덱 강화 → 경기
- 루프2 : 리그/시즌 → 랭킹/칭호 → (한정 보상) → 신규 카드/시스템 해금
- 루프3 : 구단 운영(선수 및 치어리더 영입) → 선수 풀 확장 → 메타 적응

✅ **[구현 확정]** 루프1(경기-보상-성장-강화)과 루프3(선수/치어리더 영입)의 백엔드 파이프라인은 실제
구현되어 있다(`MatchEngine`/`LeagueManager`/`RosterManager`/`ScoutManager`(선수)·`CheerleaderGachaService`
(치어리더)). 루프2(랭킹/칭호/시즌 해금)는 🕳️ **[TBD]** 미구현이다.

### 주요 게임 모드 - PvE (리그 시즌)

게임 내 '경기(Match)'는 유저의 로스터와 KBO 9개 가상 AI 팀 간의 3연전 스케줄로 구성된다.

- 리그 난이도 및 정규시즌 경기 수(9개 난이도 × OVR 기준 × 경기 수, 루키~챔피언스 리그)
- 모든 리그 정규시즌 종료 후 포스트시즌(1~5위): 와일드카드 결정전 → 준플레이오프(3전제) → 플레이오프(3전제) → 한국시리즈(4전제)
- 리그 난이도별 차등 보상 지급(훈련 돌파권, 강화 카드, 스카우트 티켓, 경험치 카드, 포인트 등)

> ✅ **[구현 확정, 페넌트레이스 구조]** `LeaguePhase` enum(`STOVE_LEAGUE`/`REGULAR_OPEN`/`REGULAR_LOCKED`/
> `POST_PREP`/`POST_SEASON`)이 5단계 시즌 흐름을 코드로 정확히 구현하고 있다(`Assets/Scripts/Models/Types.cs`).
> 🕳️ **[TBD: 기획 확정 필요]** 9단계 난이도 티어, 리그별 경기 수, 포스트시즌 대진표(와일드카드~한국시리즈)
> 구조 자체, 리그 보상 테이블은 여전히 미구현이다.

**정규시즌 (랭킹 챌린지)**

- 순수 시뮬레이션(자동) 진행만 존재한다 — 유저가 직접 관전할 필요 없이 결과만 집계되어 플레이 피로도를
  낮춘다. 원안에 있던 "매칭 후 두 유저가 함께 접속해 진행" 방식은 폐기되었다.
- 순위는 원안과 동일한 기준을 우선 재사용한다 : 1순위 승률 → 2순위 상대 전적 → 3순위 득실차 → 4순위
  다득점 → 5순위 상대 평균 OVR (🕳️ **[TBD: 기획 확정 필요]** 비동기 구조에서 "상대 전적"을 어떻게 정의할지는
  후속 확정 필요).

**포스트시즌 (가을야구) — 비동기 스코어 경쟁**

- 정규시즌과 달리 주말 특정 시간대에만 오픈한다(예 : 토요일 와일드카드 결정전).
- 참가한 두 유저는 각자 자신의 로스터로 **동일한 가상 AI 상대**를 상대로 개인 플레이를 진행한다 — 진행
  방식은 빠른 진행 / 하이라이트 / 풀 플레이 중 택 1(🕳️ 아래 "조작 및 인터페이스" 절 참고, [결정 필요]).
- 양측의 플레이가 각각 종료되면, 서버(BaaS)가 두 유저의 결과(스코어)를 비교해 더 높은 쪽을 승자로
  판정한다 — 두 유저가 동시에 접속해 경기를 주고받는 것이 아니라 "각자 따로 친 스코어를 나중에 비교"하는
  방식이므로 두 유저가 같은 순간에 접속할 필요가 없다.
- 지정된 시간대에 미참여 시 노쇼(No-show) 패널티로 자동 기권패 처리한다.
